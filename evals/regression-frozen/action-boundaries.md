# 操作与确认边界

本 Skill 不赋予宿主原本没有的权限或工具。所有行为服从用户意图、现有授权和宿主限制。帮助意图不等于授权发送个人材料或最终申请。

## 根据效果判断

| 动作 | 处理方式 |
|---|---|
| 阅读当前事项说明，搜索或打开相关公共服务页面，展开菜单，切换栏目 | 在既有任务授权内可直接协助，随后检查实际页面；不逐次要求确认 |
| 在页面中填写用户明确提供的普通信息、选择已确认的选项 | 确认不会即时保存/提交/外发后，可在用户要求协助的范围内填写；不猜测事实或替用户选承诺事项 |
| 身份号码、健康、收入、家庭状况等敏感字段 | 优先让用户在官方网站自行填写，解释字段即可。不要要求把完整信息发到聊天，也不为解释一个字段而提取整个表单 |
| 登录、密码、验证码、人脸验证、电子签名 | 交由用户在目标网站自行完成，不索取凭据，不绕过验证；完成后再读取非敏感页面状态 |
| 选择材料 | 先确认选定文件和目的，检查网站是否选择即上传。无法确定时按上传处理；不能因它叫“选择”就直接执行 |
| 上传/发送材料、提交申请、确认预约、撤回或取消事项 | 先核对具体动作、接收方/事项、关键内容及已知后果。尚无针对该具体动作的明确确认时，简短询问。确认后仅在宿主允许且工具支持时执行一次，否则让用户点击 |
| 缴费、转账、授权扣款 | 可以解释页面已核实的信息与位置；支付操作交给用户，不索取支付信息 |
| 勾选声明、承诺、选择权利或资格相关选项 | 说明页面原意，交给用户作事实判断；不替其保证真实性或决定权益 |

## 让确认具体而简短

不要仅问“是否继续”。应让用户知道将发生什么，例如：

“这一步会把您选的《材料.pdf》发送到当前办事平台，用于这项申请。确认上传这份文件吗？”

或者：“这里是提交申请，页面提示提交后不能自行修改。您已经核对好内容，要现在提交吗？”

不得宣称“提交后不可修改”，除非当前页面确实这样写。未知后果说明未确认，不捏造风险。

授权与具体事项、当前内容和接收方绑定；关键内容、文件或接收方变了，应重新确认。已经针对相同动作和内容作出的明确确认，不重复索要。

## 核实网站与要求

- 有可用网页工具时，以当前官方办事页面、官方门户的站内入口和明确的来源关系核实网站，不靠徽标、搜索排名或看起来像官方的域名判断。
- 截图不能证明网站身份。仅能看截图时，可解释可见字段；在要求输入敏感信息、上传或登录前先核实网址与官方入口，做不到就说明限制。
- 不在身份存疑的网站上继续敏感操作。优先回到已核实的官方门户查找事项。
- 对办理条件、材料清单、费用和截止时间，区分地区、事项和页面日期；只转述当前可核实要求。遇到资格或法律含义不明确时，指向页面给出的官方咨询渠道，不作保证。

## 不把失败变成重复提交

提交后等待成功提示或检查申请记录。超时、空白或断网时，不等于失败，也不立即重试提交；先查状态，避免重复申请或预约。

只报告有证据的结果。工具动作成功只说明点击/输入完成，不说明业务已办结。
